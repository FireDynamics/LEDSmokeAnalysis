apply_moving_average() → None[source]

Replace the reference property of every LED by its centred moving average over num_moving_avg_images consecutive analysed images, fewer at the start and the end of the series. The noise, where it is used, becomes the standard deviation of that mean, so the root of the summed variances divided by the number of images.

Every image keeps its own time and its own row, so the series is smoothed rather than decimated: the time resolution becomes num_moving_avg_images times the image interval while the number of extinction coefficients stays the same. average_images with n_summarize is the other way round.

apply_temperature_correction() → None[source]

Divide the reference property by the reduction factor of the time and height of every value.

Does nothing if the channel has no reduction factors configured or if they were divided out already, so that the factors enter the intensities exactly once however often this is called.

The correction runs before the reference intensities are averaged, so that I0 is a corrected intensity as well and the reduction of the reference images cancels out of the relative intensities. The factors are looked up on the (img_id, led_id) index of the loaded data rather than on a positional array, because the LED axis of the intensities is ordered by LED ID while the distance matrix follows the reversed LEDs of the experiment.

Raises:

ValueError – If an image or an LED of the loaded data has no time or height.

class ledsa.analysis.ExtinctionCoefficientsLinear.ExtinctionCoefficientsLinear(experiment, reference_property='sum_col_val', num_ref_imgs=10, average_images=False, ref_img_indices=None, lambda_reg=0.001, n_summarize=2, temperature_correction=None, snr_full_weight=10.0, min_layer_weight=0.5, num_moving_avg_images=1)[source]

Bases: ExtinctionCoefficients

ExtinctionCoefficientsLinear computes the extinction coefficients by linearizing the Beer–Lambert law. Specifically, using the transformation:

-ln(I_e / I_0) = sum_i (sigma_i * Delta s_{i})

the problem is recast as a linear least squares system that can be solved efficiently. A Tikhonov regularization is added via a finite-difference operator to enforce smoothness in the solution.

Variables:

solver (str) – Type of solver (linear or nonlinear).

calc_coefficients_of_img(rel_intensities: ndarray, snr: ndarray = None) → ndarray[source]

Calculate the extinction coefficients for a single image using a linearized approach. This method solves the linear system derived from the Beer-Lambert law using non-negative least squares with Tikhonov regularization.

LEDs whose relative intensity is at or below zero are left out: their signal has vanished in the noise of the sensor, so they carry no information on the extinction. If fewer than one LED with full weight is left, the image yields NaN. An LED whose noise is unknown keeps the full weight, because a missing noise estimate is no reason to drop a measured intensity.

If snr is given, every LED is weighted with min(1, snr / snr_full_weight). The standard deviation of the optical depth -ln(I_e/I_0) is about 1/snr, so the weight is the inverse standard deviation, capped so that well measured LEDs keep the weight 1 and the meaning of lambda_reg does not change. LEDs with a signal at or below zero get the weight 0. If the weights add up to less than one LED with full weight, no coefficients can be computed and NaN is returned. Layers in which the path length weighted mean weight of the crossing LEDs stays below min_layer_weight are set to NaN as well: their coefficients would rest on LEDs near the noise level, where the linearised Beer-Lambert law is biased.

Parameters:

  • rel_intensities (np.ndarray) – Array of relative (normalized) LED intensities (I_e/I_0).

  • snr (np.ndarray or None) – Signal-to-noise ratio of every LED, or None for equal weights.

Returns:

Array of the computed extinction coefficients (sigmas).

Return type:

np.ndarray

class ledsa.analysis.ExtinctionCoefficientsNonLinear.ExtinctionCoefficientsNonLinear(experiment, reference_property='sum_col_val', num_ref_imgs=10, ref_img_indices=None, average_images=False, weighting_curvature=0.01, weighting_preference=-0.006, num_iterations=1000, n_summarize=2, temperature_correction=None)[source]

Bases: ExtinctionCoefficients

ExtinctionCoefficientsNonLinear computes the extinction coefficients by directly minimizing the difference between observed and predicted intensities using the Beer-Lambert law:

I_e = I_0 * exp(-sum_i (sigma_i * Delta s_{i}))

A numerical optimization approach is used with regularization terms to enforce smoothness in the solution. The cost function is

rmse(sigma) + weighting_curvature * mean((D2 sigma)^2)

  • weighting_preference * mean(sigma),

where rmse is taken over the LEDs and D2 is the second difference over the layers. Every term is a mean, so the weights keep their meaning for any number of LEDs and layers.

Variables:

  • bounds (list[tuple]) – Bounds for each layer.

  • weighting_preference (float) – Weighting factor for the preference to push the numerical solver to high or low values for the extinction coefficients.

  • weighting_curvature (float) – Weighting factor for the smoothness of the solution.

  • num_iterations (int) – Maximum number of iterations of the numerical solver.

  • curvature_operator (np.ndarray) – Finite difference operator of the second derivative over the layers.

  • solver – Type of solver (linear or nonlinear).

The traversed distances are accumulated per layer, so the part of a light path that lies outside the layers is lost. Computing extinction coefficients from such a path would attribute the dimming of the whole path to the layers covering a part of it.

request_config_parameters() → None[source]

Prompts the user to input missing parameters of analysis configuration and updates the configuration.

Correction of the LED intensities for the temperature of the LEDs.

An LED loses radiant power as it heats up, so the LEDs in the hot gas layer dim over the course of an experiment without any smoke between them and the camera. Left uncorrected, that drift enters the relative intensities as an extinction that is not there.

The factors the intensities are reduced by are measured or modelled outside LEDSA and read from one file per camera channel, as a table of the reduction factor over the experiment time and the height of the LED. LEDSA interpolates that table bilinearly to the time of every image and the height of every LED and divides the intensities by it, so that an uncorrected analysis is what it was before.

The interpolation stays between the tabulated times and heights. The table states where the reduction of the LEDs was determined, so an image or an LED outside it is left exactly as it was extracted rather than corrected with a factor the measurement does not cover.

Stacked Multi-Camera Analysis

Stacked extinction coefficient computation across multiple cameras/LEDSA runs.

Usage example:

from ledsa.analysis.ConfigDataStacked import ConfigDataStacked
from ledsa.analysis.StackedExtinctionCoefficients import StackedExtinctionCoefficients

cfg = ConfigDataStacked()                    # reads config_stacked.ini

for reference_property in cfg.reference_properties:
    for arr_id in cfg.get_led_array_ids():
        for channel in cfg.camera_channels:
            sec = StackedExtinctionCoefficients(cfg, arr_id, channel, reference_property)
            sec.calc_and_set_coefficients()
            sec.save()
class ledsa.analysis.StackedExtinctionCoefficients.StackedExtinctionCoefficients(config: ConfigDataStacked, led_array_id: int, channel: int, reference_property: str | None = None)[source]

Bases: object

Joint inversion of extinction coefficients using ray data stacked across multiple cameras (LEDSA simulation directories).

For a given virtual LED-array ID and colour channel the class:

  1. Builds one Experiment per (simulation, led_array_id) pair.

  2. Constructs a stacked system matrix by vertically concatenating the per-experiment distance-per-layer matrices and writes it once per virtual array (channel-independent) to <output_path>/.

  3. Computes the common time axis across all simulations, writes a time-alignment report to <output_path>/, and stores it for reuse.

  4. Solves the augmented Beer–Lambert system with the configured solver.

  5. Writes extinction coefficient CSVs to <output_path>/analysis/extinction_coefficients/<solver>/<reference_property>/.

Variables:

  • config (ConfigDataStacked) – Stacked-analysis configuration.

  • led_array_id (int) – Virtual LED-array ID (integer key in [led_arrays]).

  • channel (int) – Colour channel index.

  • reference_property (str) – Quantity the coefficients are computed from.

  • layers (Layers) – Shared layer discretisation.

  • led_array_mapping (dict[int, int]) – {sim_idx: led_array_id} for this virtual array.
